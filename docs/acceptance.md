# 多语言参考服务验收记录

验收日期：2026-09-20。实现位于本参考工程，设备固件未修改。

## 软件验收

| 项目 | 结果 |
| --- | --- |
| Python / FastAPI | 63 项单元测试通过 |
| Go / 标准库 HTTP | 145 个测试及子测试通过；race、vet 通过 |
| Java / Spring Boot | 54 项测试通过；完整服务及旧 CLI 均完成打包 |
| JavaScript / Express | 45 项测试及 TypeScript 类型检查通过 |
| 共同协议 | 33 个命名业务 RPC 的 JSON 与 Protobuf 共享样例通过；协议文件校验和通过 |

| 容器交付 | 四个服务镜像构建成功；Compose 同时启动后健康检查、带鉴权设备查询及数据卷写入通过 |
| 旧入口兼容 | `./tests/run_smoke.sh all` 通过四种语言的 Protobuf、JSON 旧示例回归 |

Go 的数字包含子测试，不应与其他语言的测试数量直接比较。CI 已加入相同验证流程；本记录报告本地执行结果，不代表远程 GitHub Actions 已运行。

黑盒测试为每个服务配置两个独立 Broker，以及 JSON、Protobuf 设备，覆盖：

- 33 个命名业务路由、并发 RPC、跨连接/设备隔离、设备错误、结果未知超时、能力限制、非法参数和 HTTP 鉴权。
- 最新遥测及接收计数持久化、告警重复去重、相同时间戳状态核对、Webhook 失败重试和稳定幂等键。
- 图像分块乱序、服务重启后续收、文件校验后确认、确认失败重试，以及拒绝未经本地校验的证据确认。

各语言单元测试另覆盖存储失败、容量及保留策略、生命周期通知策略、非法/超限图像、安全解包等边界。测试通过并不构成弱电环境零丢失或端到端恰好一次的保证。QoS 0 不提供可靠补偿；Webhook 下游仍须使用幂等键去重。

## 实机只读检查与未完成项

已通过用户指定 SSH 入口进行只读检查，确认设备进程运行，并核对设备的 MQTT 配置及编码类型。工作站连接设备配置的标准 MQTT Broker 时收到连接拒绝，因此尚未完成真实设备 MQTT 查询、订阅及上报验收。未执行配置修改、测量启停、删除标靶、重启或断电测试。

所有型号专属能力目前仅标记为“契约测试通过／未实机验证”，详见[覆盖清单](coverage.md)。模拟器用于验证客户端协议和服务行为，不能证明每一种硬件支持对应能力。

后续实机验收步骤：

1. 恢复从测试环境到设备所用 Broker 的可达性，在本地配置文件和环境变量中填写连接信息。
2. 查询设备信息、属性、当前告警和证据状态，订阅实际遥测，核对返回值与设备状态。
3. 对配置修改、测量启停、标靶删除及重启分别取得授权；先保存原状态并记录恢复步骤，再执行和回读。
4. 为其他型号分别补充实机记录，不从当前模拟器或单台设备推断型号支持情况。

本仓库不保存真实设备地址、凭据或密钥。软件交付已完成，真实设备 MQTT 验收仍待上述条件满足。
